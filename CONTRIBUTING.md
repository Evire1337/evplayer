# Как участвовать в EvPlayer

Спасибо, что хотите помочь. Здесь описано, как ведутся задачи и как прислать изменения. Как устроен код, как его писать и тестировать — в [AGENTS.md](AGENTS.md). Его же стоит дать своему ИИ-ассистенту перед работой.

## Задачи: доска «EvPlayer»

Все задачи ведутся на доске [github.com/users/Evire1337/projects/2](https://github.com/users/Evire1337/projects/2). Доску ведёт автор проекта (и его ИИ-ассистент).

**Каждая задача — карточка с названием и описанием.**
- **Название** — коротко, что должно получиться для пользователя, с областью в начале: `Jam: после выхода из сессии музыка играет дальше`, `Android: виджет средней высоты`.
- **Описание** — что сейчас не так или чего не хватает, что должно быть в итоге, как проверить. Для ошибки — как её повторить и на какой системе.

**Статус** — колонка доски:

| Статус | Когда |
|---|---|
| **Todo** | задача записана, работа не начата |
| **In Progress** | над задачей работают; сюда же — сделано, но ещё не проверено на деле |
| **Done** | сделано и проверено |

**Категория** — поле «Категория», у каждой карточки одна из двух:

| Категория | Что сюда | Примеры |
|---|---|---|
| **Нововведение** | то, что решено сделать и делается или уже сделано: новые функции, исправления, улучшения, сборка и CI | «Android: уведомление плеера не пропадает», «Диагностика: что сколько ест ОЗУ и ЦП» |
| **What is wanted** | пожелания и идеи, за которые ещё не взялись: «было бы хорошо», просьбы пользователей, мысли на потом | «Импорт из Apple Music», «Тема оформления на выбор» |

Когда за пожелание берутся, его категория меняется на **Нововведение**, а статус — на **In Progress**.

Если у вас нет доступа к доске, откройте [issue](https://github.com/Evire1337/evplayer/issues): ошибку — с меткой `bug`, пожелание — с меткой `enhancement`. Автор перенесёт его на доску.

## Как прислать изменения

Вносить изменения напрямую в репозиторий могут только участники с доступом. Все остальные присылают **pull request**, и **автор просматривает каждый вручную**: ничего не попадает в проект само.

### 1. Подготовка

1. Сделайте fork репозитория.
2. Создайте ветку **от `tauri`** (не от `main`: там нет кода):
   ```bash
   git clone -b tauri https://github.com/<ваш-логин>/evplayer.git
   cd evplayer
   git switch -c fix/short-name
   ```
   Название ветки: `fix/…` — исправление, `feat/…` — новая функция, `docs/…` — документация.
3. Пишите код по правилам из [AGENTS.md](AGENTS.md). Одна ветка — одна задача.
4. Перед отправкой проверьте:
   ```bash
   pnpm typecheck
   pnpm test
   ```
   Если меняли Rust — ещё `cargo test` в папке `src-tauri`.

### 2. Pull request

Откройте pull request **в ветку `tauri`** репозитория `Evire1337/evplayer`. Описание заполняется по шаблону, который GitHub подставит сам:

- **Что добавлено или исправлено** — по-человечески, с точки зрения пользователя;
- **Зачем** — какую проблему решает, ссылка на issue или задачу, если есть;
- **Как проверено** — на каких системах, какие шаги, какие тесты добавлены;
- **Скриншоты или видео**, если меняется внешний вид;
- **Issue «вклад»** — ссылка на него (см. ниже).

Можно открыть pull request черновиком (Draft): CI соберёт только быструю часть и установщик для Windows. Когда всё готово — нажмите **Ready for review**, и CI соберёт версии для всех систем.

### 3. Issue «вклад»

К каждому pull request стороннего участника открывается issue с меткой **`вклад`**: короткая запись о том, что было добавлено. Так в одном месте видно, что и кем внесено в проект.

1. Откройте [новый issue](https://github.com/Evire1337/evplayer/issues/new/choose) и выберите шаблон **«Вклад: что добавлено»**. Метка `вклад` поставится сама.
2. Заполните: что добавлено, ссылку на pull request, какие части проекта затронуты.
3. Вставьте ссылку на этот issue в описание pull request.

### 4. Проверка автором

- Автор читает код и описание, при необходимости запускает сборку из CI и проверяет на деле.
- Замечания приходят комментариями в pull request. Исправляйте новыми коммитами в ту же ветку — pull request обновится сам.
- Когда всё в порядке, автор сливает pull request в `tauri` и закрывает issue «вклад». Изменение выйдет в ближайшем релизе.
- Если изменение не подходит проекту, автор объяснит почему и закроет pull request.

## Сообщения коммитов

На английском, первая строка — что изменилось для пользователя, с областью в начале:

```
Jam: guests no longer play their own songs when only the host may
```

Подробнее — в разделе «Коммиты» в [AGENTS.md](AGENTS.md).

## Чего не присылать

- Изменения версии, ключей подписи и обновлений, настроек релиза — это делает автор.
- Сразу много несвязанных изменений в одном pull request — разделите их.
- Код, скопированный из чужих проектов без совместимой лицензии. Проект под [MIT](LICENSE), и ваш вклад тоже будет под ней.
